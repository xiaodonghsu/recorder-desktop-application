# VoiceHub Microphone

将 CAC10 蓝牙录音卡作为无线语音采集端，通过 Python 桌面应用完成离线语音转文字，结果可编辑、复制到其他应用。使用 uv 管理 Python 环境。

## 运行

已在 Windows / Python 3.12 验证依赖安装与自动化测试。

```powershell
uv sync
uv run voicehub-models
uv run voicehub
```

首次模型下载需要联网（SenseVoice 模型约数百 MB）。下载后，接收音频、解码、VAD、ASR 全部在本机完成。验证成功后自动记住蓝牙名称、MAC 地址与 AuthKey：名称和地址存入本机用户设置，AuthKey 存入系统凭据库（Windows 使用凭据管理器），不以明文写入配置或日志。下次扫描并选中相同 MAC 的设备时自动填入密钥；验证失败的密钥不会保存，也不会覆盖原有凭据。凭据库不可用时会提示保存失败，本次连接仍可使用。

1. 打开录音卡、开启电脑蓝牙，退出其他占用录音卡的客户端。
2. 应用启动自动扫描 6 秒，列出广播名称以 `CAC10` 开头的设备。
3. 选择设备，输入 64 位十六进制 AuthKey（可带 `0x`），点击“连接并验证”。
4. 认证成功后自动读取电量、增益、容量、固件和 SN，保留当前页面。切换到“实时语音”即可开始使用，也可点击“进入后台”使用托盘。
5. 按下录音卡录音键，应用收到按键事件 1（`TYPE=3 / CMD=1`）后自动开始接收音频；后台运行时同样有效。再次按键后，收到停止/保存事件 3（`TYPE=3 / CMD=3`）会自动发送停止推流命令、结束收音。若固件再次上报事件 1，也会按当前录音状态切换为停止。也可从托盘或主窗口操作。
6. 接收过程中在独立音频线程逐包将 Opus 实时解码为 16kHz 单声道 PCM，界面显示已解码时长。再次按录音卡按键或选择“停止录音并识别”后，程序排空已收到的尾包并复用 PCM，执行 Silero VAD → SenseVoice 本机离线识别。识别完成显示窗口，点击“复制全部文字”。
7. 关闭窗口会进入后台；右键托盘“退出”会停止接收并断开设备。转写期间等待识别完成后退出。

连接后设备信息补充显示 SN，按[蓝牙录音卡通信协议](https://raw.githubusercontent.com/xiaodonghsu/recorder-browser-cli-demo/master/docs/%E8%93%9D%E7%89%99%E5%BD%95%E9%9F%B3%E5%8D%A1%E9%80%9A%E4%BF%A1%E5%8D%8F%E8%AE%AE.md)的 2026-11-21 修正，通过 AE21 发送无参数的 `0-12`，等待 `0-13` 应答，将全部载荷按 UTF-8 解码为 SN，无状态码前缀、不截取固定长度，也不依赖标准 `180A/2A25` 服务。手动刷新时重新读取；空应答、写入失败、无效 UTF-8 或等待 5 秒超时显示未知，并继续读取其他设备信息。SN 查询超时保留已验证连接；断开连接后清除显示，迟到的 SN 应答不会主动更新界面。仍需目标 CAC10 实机验证。

可指定数据目录（默认相对于启动目录）：

```powershell
uv run voicehub-models --dir D:\VoiceHub\models
uv run voicehub --models D:\VoiceHub\models --recordings D:\VoiceHub\recordings
```

模型目录布局：

```text
models/
  silero_vad.onnx
  sense-voice/
    model.int8.onnx
    tokens.txt
```

## 界面布局

- **设备连接**：扫描、AuthKey 验证、连接与断开，以及设备信息。
- **实时语音**：录音控制、实时转写、输入当前窗口、虚拟麦克风输出及实时文字。
- **录音与解析**：卡端文件下载与删除、本地录音转写与编辑、已有解析结果、解析输入 JSON 导出，以及原始 `.vhrec` 录音恢复。原始录音恢复的转写结果在本页显示。

顶部始终显示设备连接、电量和任务状态；录音时显示时长及停止按钮。切换 Tab 不会中断录音或文件任务，应用记住上次使用的 Tab。文件任务与录音互斥，暂时不可用的操作会禁用并显示原因；未连接设备时仍可处理本地文件。

“高级设置”集中提供模型目录、音频分包模式、录音文件本地保存目录、独立语句按键指令和诊断日志，模型与分包配置供实时录音和原始文件转写共用。自动总结模型尚未接入，解析区支持查看已有结果与导出输入 JSON。

## 录音与恢复

每次录音保存于 `recordings/`：

| 文件 | 内容 |
| --- | --- |
| `.vhrec` | 原始 BLE 音频载荷，保留每包长度及到达时间 |
| `.json` | 收包数、字节数、结束原因等元信息 |
| `.wav` | 实时解码完成后保存的 16kHz 单声道 PCM16；也支持离线重解码 |
| `.txt` | 完整识别文字 |
| `.segments.json` | VAD 语音段起止时间与文字 |

断连、停止超时、解码失败均保留已收到的原始音频。在“录音与解析”选择“原始录音恢复”，打开 `.vhrec` 可在调整模型目录或分包模式后重试。单次接收限制为 128 MiB 或一小时；达到限制后保存原始音频并要求重连。录音和文字留存在本地目录，可自行删除。

本应用的 `.vhrec` 格式是 `VHREC001` 八字节文件头，加重复的 `payload_length:uint32 LE + elapsed_seconds:float64 LE + payload`，与浏览器项目 `.vhstream` 格式不同。

录音中 PCM 写入 `.wav.part`，停止或断连后排空解码队列、刷新解码器及重采样器，再完成 `.wav` 文件。实时解码使用有界队列，不阻塞蓝牙通知线程；解码失败或队列积压会明确报错，原始音频仍继续保存，可停止后调整分包模式重新转写。实时解码在本地完成；VAD/ASR 在停止后执行。

## 协议与固件边界

- 使用 AE20 服务，AE21 整帧写入；分别为 AE22、AE23 建立组帧缓存。AE22 必须可订阅，AE23 可选。
- 对 AE22、AE23 中校验通过的 `3-1`、`3-3` 帧分别上报开始/停止按键事件；相同 SEQ、CMD 和载荷的通知在 500ms 内去重，避免双通道重发导致误切换。仅鉴权通过后允许自动录音，鉴权后读取设备信息期间的开始按键会等待当前操作完成。启动尚未完成时再次按键，会在启动确认后立即停止；停止和识别期间不会重复启动。
- CRC-16/XMODEM 覆盖 LEN 原始两字节和 DATA；处理半帧、多帧、损坏帧；单字节 ACK 不作为业务成功。
- 只有 `0-51` 应答首字节为 0 才算认证成功，认证超时断连，不自动放行。
- 请求串行执行，按 TYPE/应答 CMD 匹配；普通请求超时后断开，避免迟到应答被后续同类请求误用。SN 只读查询按协议单独处理：超时显示未知并保留连接，继续读取其他信息。
- “录音”按钮使用 `1-0` 开始实时推流、`1-2` 停止推流；不发送管理设备内存储录音文件的 TYPE=3 开始/停止命令。
- 开始必须等到 `1-0` 文件名或 `1-1` 音频通知。停止等待 `1-4 state=2`；超时保留音频并要求重连。
- 默认每个 `1-1` 载荷视为一个标准 Opus 包。该假设需要在目标固件真机确认；不删除 `4B 41`，不猜测私有头。
- 如已确认实时载荷为已知 40 字节 Opus 包的组合，可手动选择 `fixed40` 模式。该模式检查长度和已知包结构，不自动套用下载样本结论。
- 容量按浏览器实现的 1KiB/单位显示估算值，界面标明估算；原参考协议另有 8KiB 单位描述，需要按目标固件核实。
- 断开即清除本次连接的授权状态，已验证的设备凭据保留供下次连接使用；不自动重连。BLE 链路上的 AuthKey 是协议规定的明文载荷。

本应用支持文字转写和实时输出到现有虚拟声卡；不会自行安装驱动或注册操作系统虚拟麦克风。启用“将实时文字输入到当前窗口”后，可通过 Windows Unicode 键盘事件向当前输入框追加已确认文字。

## 边说边转写并输入当前窗口（Windows）

1. 使用 `uv run voicehub-models` 准备原有 Silero VAD 和 SenseVoice 模型，重新启动 VoiceHub。
2. 勾选“边说边转写”。若要直接输入其他应用，再勾选“将实时文字输入到当前窗口”；仅勾选前者时，识别文字只显示在 VoiceHub 中。两个选项默认关闭。
3. 连接并验证录音卡，将光标放到目标应用的输入框，按录音卡按键开始说话。也可以在 VoiceHub 中点击开始，再切到输入框；此时首次文字输出时绑定目标窗口。
4. 短暂停顿（约 0.4 秒）或连续说话约 3 秒后，模型识别一段并追加文字，录音继续进行。输出还需加上本机推理时间，首次启动需要加载模型。这是复用现有离线模型的短句实时转写，不是逐字滚动的流式模型；强制分段可能影响跨段词语和上下文准确率。
5. 再次按键停止后，会排空已收到尾包、识别剩余语音并保存 `.wav`、`.txt`、`.segments.json`，不会把已输入文字再次发送，也不会抢走前台窗口。实时模式下“停止后自动进行离线转写”不再额外执行；如需整段重新识别，可在“录音与解析 → 原始录音恢复”选择 `.vhrec` 文件重新转写。

自动输入不修改剪贴板。启用输入当前窗口时，独立语句按键指令默认开启：先说完正文并停顿约 0.4 秒，再单独说“回车”并停顿约 0.4 秒，即发送 Enter；单独说“换行”发送 Shift+Enter。首尾空白和标点会被忽略，例如“ 回车。”也能匹配；“请按回车继续”“回车。换行”仍输入原文。只匹配完整停顿后的整段识别结果，不在句子中替换词语；连续语音被提前分段、或停止录音时没有足够停顿的尾句不会执行指令。原始识别文字仍显示并保存。

在“高级设置 → 独立语句按键指令”中可关闭功能或编辑映射，每行使用 `指令 -> 按键`，支持 `Enter`、`Shift+Enter`、`Ctrl+Enter`、`Tab`，点击“保存按键指令设置”后立即生效并记住配置。默认配置为 `回车 -> Enter`、`换行 -> Shift+Enter`。Enter 或 Ctrl+Enter 在部分应用中会发送消息，实际行为由目标应用决定；模型输出中的普通换行仍只转换为空格。

文字和按键发送前都会核对前台窗口、进程及原生焦点控件；发生变化、按下 Shift/Ctrl/Alt/Win 或系统拒绝输入时，本次自动输入暂停，后续识别仍保留在 VoiceHub，可手动复制。停止后重新开始可绑定新窗口。Windows 原生焦点句柄无法区分某些浏览器中共享同一控件的不同网页输入框，也无法判断用户在同一输入框内移动光标；输入时请保持目标位置。管理员权限窗口或部分特殊编辑器可能不接受模拟输入，失败时请核对已有文字再手动复制，避免重复。

解码、实时识别和音频输出互相独立，识别队列最多缓存约 15 秒 PCM；识别跟不上时明确报错并停止本次实时识别，原始录音和 WAV 仍会保存，已确认文字增量落盘，可在停止后重新转写。此功能不依赖 VB-CABLE，可与虚拟麦克风输出同时使用。

## 作为虚拟麦克风使用（Windows）

1. 从 [VB-Audio 官网](https://vb-audio.com/Cable/) 安装 VB-CABLE，按安装程序要求重启电脑。
2. 重新启动 VoiceHub，在“实时音频输出”中选择 `CABLE Input`（优先 Windows WASAPI），不要选择 `CABLE Output`。默认关闭输出，不会自动播放到扬声器。设备列表显示主机音频接口，同一设备可能出现多次；安装或插拔设备后建议重启 VoiceHub，刷新按钮可重新枚举当前音频后端已发现的设备。
3. 在会议软件、浏览器或录音软件中，将麦克风选择为 `CABLE Output`。
4. 如只需要麦克风，取消“停止后自动进行离线转写”，此时无需下载识别模型。连接并验证录音卡后，点击“开始录音”或按录音卡按键，音频会边解码边输出；停止后仍会保存原始录音与 WAV。需要文字时可重新转写文件。
5. 启用自动转写时，停止后仍执行原有本机 VAD/ASR；输出设备异常不会中断原始录音保存或 PCM 解码，界面单独显示输出状态。

实时输出从 16kHz 单声道 PCM 转换到目标设备的默认采样率，支持单声道或双声道。输出使用约 60ms 起始缓冲、最多 300ms 音频队列；缺包时补静音，积压时丢弃最旧输出音频以限制延迟，缓冲异常会写入日志。这些调整仅影响实时输出，WAV 保留完整已解码音频。缓冲上限不代表端到端延迟上限，BLE、系统及目标应用还会引入延迟。

录音卡必须实际开启实时推流才有声音，应用停止录音后不会持续采集。断连或停止后排空已接收尾包并关闭输出，下一次录音使用全新缓冲。当前仍需 CAC10 实机及 VB-CABLE 联合验证连续收音、延迟与目标应用兼容性；软件不会把 BLE 录音卡直接配对成标准蓝牙耳麦。

```

$env:VOICEHUB_TEST_WAV = "D:\samples\speech.wav"

```

## 录音卡文件管理

切换到“录音与解析”Tab，左侧选择“本地录音”或“卡端文件”，右侧查看、编辑转写和已有解析结果：

1. 连接并验证录音卡后，在“录音卡文件”中点击“读取文件列表”。支持 Ctrl / Shift 多选、批量保存、下载并 ASR，以及卡端删除。
2. 首次默认保存到启动目录的 `Sounds/`，可在“高级设置 → 录音文件本地保存目录”中选择目录；应用会记住选择。“本地录音”栏目下的“打开目录”可打开当前保存目录。用设备 SN + 卡端列表原始文件名作为唯一标识，生成固定 ID 目录。同一设备的同名录音重复下载会复用本地记录；不同 SN 的同名文件分别保存。原始文件名完整参与标识，不使用补全后的下载名称。读取不到 SN 时，请先刷新设备信息再下载。
3. 列表原名（包括结尾的 `.`）完整保留。下载优先把末尾句点替换为 `.opus`，仅在设备明确返回“文件不存在”且未收到数据时尝试 `.wav`、列表原名。卡端删除发送列表原始条目，不用补全后的文件名。
4. 在“本地录音”中多选录音执行离线 ASR。点击某条本地录音查看、复制、编辑文字，编辑自动保存；重新 ASR 替换已有文本前会提示。卡端删除保留本地副本；本地删除同时删除该录音的转写与分析数据，保留卡端文件。删除前均有确认。
5. 转写仍使用本机 Silero VAD + SenseVoice 模型。下载内容按文件头识别 WAV / Ogg 并转换为 16kHz 单声道；无容器 Opus 仅接受已知且逐包校验的 40 字节格式，不根据 BLE 下载片段猜测 Opus 包边界。

每条本地录音包含 `record.json`（新记录 schema_version=2、设备 SN、设备来源、列表原始条目、下载状态、SHA-256、ASR 状态、转写文本及分段、文本版本、分析结果），以及原始 `audio.opus`、识别用 `audio.wav` 和可直接使用的 `transcript.txt`。`audio.opus` 是原始下载数据，具体编码由内容判断，设备回退返回的 WAV 也保留原始字节；`audio.txt` / `audio.segments.json` 是 ASR 引擎的原始输出。编辑后以 `record.json` 和 `transcript.txt` 为准，原分段会标记 `segments_match_text=false`。

点击“导出解析输入 JSON”可导出带录音 ID、来源、音频摘要、文本版本及分段的模型输入。代码提供 `Library.analysis_input(record_id)` 与 `Library.save_analysis(record_id, kind, model, result, transcript_revision)`，后续可接入不同模型，并记录分析所依据的文本版本；当前不调用大模型。

文件操作期间暂停新的录音操作。列表仅在收到明确结束通知后标记完成；15 秒未完成会断开连接，避免误用不完整列表。下载收到完成状态才转为正式文件；失败保留 `.part` 和失败记录，重新连接后重试会沿用同一记录并从头下载，当前不提供断点续传。完整下载的本地录音直接复用；“下载并 ASR”仅在尚无转写时执行识别，保留已有转写、编辑及解析。如需替换已有转写，请使用本地录音的 ASR 操作。缺少 SN 的历史记录仍可查看和处理，不自动推断 SN 或合并。批量操作遇到失败会停止，已完成结果保留。文件协议与下载音频格式仍需目标 CAC10 固件实机验证。

### WiFi 高速传输（Windows）

在“录音与解析 → 卡端文件”勾选“高速传输”，输入要设置的 **8–16 个字符 WiFi 密码**，再点击“保存所选到本地”或“下载并 ASR”。首次连接或修改密码时，应用通过蓝牙 `0-62` 设置密码，收到 `0-63` 的单字节成功结果后才继续。已开启或开关状态未知的热点会先关闭，再开启以应用新密码、读取 SSID，随后通过 Windows WLAN 连接热点，建立 `192.168.1.1:27689` TCP 连接。同一会话、同一密码的已确认连接可直接复用。电脑的 WiFi 会切换到录音卡热点，原网络连接可能中断；使用完后可在系统中切回原网络。

文件请求始终通过蓝牙发送，蓝牙须保持连接；高速模式仅从 TCP 接收下载数据，复用 CRC 校验及独立流式拆帧，避免双通道重复写入。TCP 每 30 秒发送心跳，初次连接最多尝试 5 次，每次超时 10 秒、间隔 3 秒；下载空闲超时 30 秒。断线或 CRC 损坏不会将部分文件标为完整，保留 `.part` 以便从头重试，不在下载中途自动重连续写。取消勾选后，下一次实际下载会关闭本应用的 TCP 连接和录音卡热点，再走蓝牙。WiFi 密码不写入应用设置和日志；临时 WLAN 导入文件在导入后删除，本应用创建的手动连接配置在连接清理时删除。

依照[WiFi 与文件传输文档](https://github.com/xiaodonghsu/recorder-python-cli-web-demo/blob/master/docs/WIFI_AND_FILE_TRANSFER.md)，高速下载的短文件名使用 24 字节字段；补全扩展名后超过 24 字节的 CAC10 长文件名使用原有蓝牙下载的 29 字节兼容格式。接收通道改变不应截断原文件名。原有蓝牙下载保留 29 字节字段，两者均整帧写入 AE21。超出所选字段的候选名会跳过，继续尝试能完整容纳的 .wav 或列表原名；全部候选都过长时明确报错，保留连接，不发送截断后的名称。实际固件对字段格式的支持仍需实机核实。

已按[WiFi 控制与状态查询协议](https://github.com/xiaodonghsu/recorder-python-cli-web-demo/blob/master/docs/WiFi%E5%8D%8F%E8%AE%AE.md)核对：`0-20` 表示热点开启结果并提供 SSID，`0-22` 表示热点关闭（同时清理 TCP、终止未完成下载），`0-24/0-23` 仅表示是否有客户端连接。文档命令表把 `0-23` 列为查询应答，但状态机和坑清单强调它可能仅在状态变化时推送，TCP 已连后更不会推送，因此连接流程不强制等待 `0-23`，而以本机 SSID 和 socket 存活验证。热点开关状态仅来自本次会话的事件，蓝牙断开后清除；没有独立读取热点开关的命令。

密码按 8–16 个 Unicode 码点校验，`0-62` 参数为两字节大端 UTF-8 字节数，加密码 UTF-8 原文；不补 NUL。收到非零或无效结果即中止，不开启热点或继续下载。10 秒未收到 `0-63` 会提示固件可能不支持，并断开以避免复用迟到应答。设置成功不代表密码已生效，热点重启、电脑关联、TCP 建连均需成功才显示高速连接成功。字符能否被目标固件和 Windows WLAN 接受及完整链路仍需 CAC10 实机验证。
